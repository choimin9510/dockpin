# Dockpin

[English](README.md) · [中文](README.zh-CN.md)

macOS 메뉴 막대에서 Dock의 화면을 고정하고, 잠자기·화면 절전·모니터 재연결 후 마지막 정상 창 배치를 복원합니다. 현재 Apple Silicon / macOS 26.3.1에서 검증한 개인 사용용 앱입니다. 최소 macOS 13, 로컬 임시 서명이며 배포 공증은 하지 않았습니다.

## 사용

1. `build/Dockpin.app`을 실행합니다. 메뉴 막대의 핀 아이콘으로 설정을 엽니다.
2. 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 Dockpin을 허용합니다.
3. `잠자기 전 배치로 자동 복원`을 켜면 현재의 일반 창 배치를 자동으로 기억합니다.
4. Dock 크기까지 기억하려면 `Dock 크기 복원 권한 허용`을 누르고 System Events 자동화를 허용합니다.
5. Dock 고정 화면을 선택하고, 필요하면 `현재 배치 기억`으로 기준을 갱신합니다.

`지금 복원`은 마지막 저장 상태를 적용합니다. `현재 배치 기억`은 보호 중인 이전 기록을 현재 배치로 교체하므로, 현재 배치가 원하는 상태일 때 사용하세요. 기존 Dock 화면과 로그인 실행 설정은 유지됩니다.

로컬 빌드를 교체하면 손쉬운 사용 권한을 다시 허용해야 할 수 있습니다. 설정에서 Dockpin을 껐다 켜고 앱을 다시 실행하세요. 그래도 허용되지 않으면 기존 항목을 제거하고 현재 `build/Dockpin.app`을 다시 추가하세요. 이전 서명이 계속 남아 있으면 앱을 종료한 뒤 `tccutil reset Accessibility app.dockpin.mac`으로 Dockpin의 권한 기록만 초기화하고, 앱을 실행해 다시 허용하세요. 이 초기화는 기존 권한을 제거하며 자동으로 권한을 부여하지 않습니다.

## 복원 동작

- 창 이동·크기 변경 알림과 5초 주기 확인으로 정상 배치를 기록합니다. 화면 변경·잠자기·복원 중에는 기록을 덮어쓰지 않습니다.
- 디스플레이는 이름 대신 UUID로 구분합니다. 화면 구성이 3초간 안정되고 사용자 입력이 2초간 없으면 복원하며, 누락된 화면은 최대 60초 기다립니다.
- 같은 실행 세션에서는 접근성 창 객체를 그대로 추적합니다. 재시작 시에는 같은 앱 프로세스의 유일한 식별자·문서·제목만 연결하며, 중복 제목이나 재실행된 앱의 창을 임의로 대응시키지 않습니다.
- 좌표는 화면 기준 포인트로 저장합니다. 화면 크기가 바뀌면 작업 영역 안으로 제한하며, 복원 결과를 읽어 2pt 오차 이내인지 확인합니다. 복원 시작 후 최소 30초 관찰하고 3초간 정상인지 확인합니다. 뒤늦게 다시 바뀐 창도 재복원하며 최초 시도는 최대 60초 진행합니다.
- `AXEnhancedUserInterface`가 켜진 앱은 위치·크기 쓰기가 애니메이션으로 충돌할 수 있어, 쓰는 동안만 이 모드를 끄고 즉시 원래 상태로 복구합니다. cmux에서 크기를 늘리자마자 이전 크기로 되돌아가는 증상을 재현했습니다.
- 사용자가 드래그한 창은 해당 복원에서 제외합니다. 새 입력·잠자기·화면 변경이 발생하면 진행 중인 쓰기 작업을 취소합니다. 이미 처리 중인 단일 macOS API 호출까지 되돌리지는 않습니다.
- 일부 복원이 실패하면 실패한 창과 Dock 설정만 기존 기준을 보존하고 정상 창은 계속 저장합니다. 추적 재개 30초 후 입력이 없으면 실패한 대상만 최대 10초 재시도합니다. `지금 복원`으로 재시도하거나 `현재 배치 기억`으로 새 기준을 정할 수도 있습니다. 미연결 화면이 돌아오면 다시 시도합니다.
- System Events가 유휴 종료된 경우 백그라운드에서 실행한 뒤 자동화 권한을 검사합니다. 미실행 오류(-600)를 권한 거부로 처리하지 않습니다.
- 진단 파일에는 복원 시각, 창별 목표·실제 좌표, 시도 횟수와 실패 사유가 남습니다. 진단에는 창 제목이나 문서 경로를 추가하지 않습니다.

Dock 이동은 아래쪽 방향과 `디스플레이마다 개별 Spaces` 설정을 전제로 합니다. 대상 화면 아래의 노출된 경계로 포인터를 잠깐 옮기고, 사용자 입력이 없었을 때만 원래 자리로 돌립니다. 드래그·입력 중에는 시도하지 않습니다. 화면 아래 전체가 다른 화면에 가려졌거나 메뉴가 열려 있으면 실패할 수 있으며, 창 복원과 구분해 상태를 표시합니다. Dock 프로세스를 강제로 재시작하지 않습니다.

기존 경계 제한은 다른 화면 하단 3pt 진입을 막습니다. Option을 누르거나 드래그할 때는 우회하며, 아래쪽에 다른 화면이 있는 연결 경계는 통과할 수 있습니다. DockLock이 실행 중이면 Dock 제어만 대기합니다.

## 범위와 저장 정보

접근성 API가 위치 변경을 허용하는 일반 앱 창과 AgentBoard 본체 패널이 대상입니다. AgentBoard는 메뉴 막대 앱이어도 추적하며 `app.agentboard.panel` 식별자만 허용하므로 이름 변경 대화상자는 복원하지 않습니다. 전체 화면, Split View, 최소화된 창, 숨긴 앱, 다른 데스크탑으로의 소속 이동, 닫힌 앱·창 재실행은 지원하지 않습니다. 앱 자체의 최소 크기 제한이나 접근성 구현에 따라 일부 창은 복원되지 않을 수 있습니다.

배치는 `~/Library/Application Support/Dockpin/Layouts/`에 화면 구성별 JSON으로 저장합니다. 창 식별을 위해 앱 식별자·프로세스 실행 시각·창 제목·문서 식별자가 포함될 수 있습니다. 디렉터리 권한은 700, 파일은 600이며 네트워크 전송이나 화면 녹화는 하지 않습니다.

`~/Library/Logs/Dockpin-status.json`은 기존 Dock 고정 상태를, `Dockpin-recovery.json`은 마지막 저장·복원 결과를 기록합니다. 진단 로그에는 창 제목·문서 경로를 넣지 않습니다.

## 개발과 검증

전체 Xcode 없이 Command Line Tools로 빌드합니다. 실행 중인 Dockpin을 종료한 뒤:

```sh
./scripts/build.sh
open build/Dockpin.app --args --show
```

```sh
./scripts/test.sh
.build/native/Dockpin --self-test
./scripts/test-integration.sh
codesign --verify --deep --strict build/Dockpin.app
```

통합 검사는 손쉬운 사용 권한이 있는 터미널에서 실행합니다. 테스트 창 두 개를 열어 이동·크기 변경 후 복원하고 Dock을 다른 화면으로 옮겼다가 되돌립니다. 마우스·키보드를 잠시 사용하지 않아야 합니다. 테스트 창과 임시 저장 기록은 종료 시 정리합니다. 이전 버전 Dockpin이나 다른 Dock 제어 앱은 먼저 종료하세요.

검증 결과:

- 정상 기록 보호, 화면 식별, 좌표·축소 처리, 노출 경계, 창 식별 충돌, JSON 저장 등 자동 시나리오 10개 통과(AgentBoard 본체와 다른 대화상자 구분 포함).
- 실제 테스트 창 두 개를 서로 다른 화면에서 이동·크기 변경한 뒤 원래 상태로 복원, 2pt 기준 통과.
- 잠자기 알림을 주입한 상태에서 기록 보존, 깨어남 알림 이후 복원, 취소된 쓰기와 권한 거부 시 기록 보호 확인.
- 실제 Dock 화면 이동과 포인터 원위치 복귀, 기존 경계 제한 검사 통과.
- 실행 앱에서 손쉬운 사용 권한 적용, Dock 고정 활성화, 세 화면의 일반 창 11개 자동 저장 확인.
- 현재 UI를 별도 프로세스에서 렌더링해 배치 확인. 컴퓨터 제어 도구의 응답 시간 초과로 실제 팝오버 클릭 검증은 완료하지 못했습니다.
- 실행 앱에서 System Events 자동화 권한과 Dock 크기 기록 확인.
- `pmset displaysleepnow`로 실제 화면 절전 후 자동으로 깨워 일반 창 10개의 복원 완료 상태 확인.
- 전체 시스템 잠자기와 물리 케이블 재연결은 별도 실사용 확인이 필요합니다. 알림 주입·화면 절전 검사는 이 두 하드웨어 시나리오를 대체하지 않습니다.

이전 버전 백업은 `build/Dockpin-0.1.0.zip`에 있습니다. 복원할 때는 현재 앱을 종료하고 한 버전만 실행하세요.

업데이트 후 현재 배치를 새 기준으로 채택하려면 `open build/Dockpin.app --args --remember-current`로 시작합니다. 기존 배치를 복원하는 대신 현재 배치를 저장하므로, 현재 배치가 원하는 상태일 때만 사용하세요.

AgentBoard 외부 크기 변경·복원 회귀 검증:

```sh
xcrun swiftc -parse-as-library -I .build/native Sources/Dockpin/Platform.swift Sources/Dockpin/Recovery.swift Tests/Integration/AgentBoardResize.swift .build/native/DockpinCore.o -o .build/native/AgentBoardResize
.build/native/AgentBoardResize --recovery
```

이 검사는 실행 중인 AgentBoard를 잠시 줄인 뒤 복원합니다. `--fill`은 너비와 가로 위치를 유지하면서 작업 영역 전체 높이를 최종 배치로 채택합니다.

2026-11-17 AgentBoard 보완 적용 후 실행 확인: 손쉬운 사용·자동화 권한 활성화, 정상 추적 상태, AgentBoard `app.agentboard.panel`이 448×1,317pt로 실제 저장됨. AgentBoard의 AXPosition·AXSize 모두 외부 쓰기 가능 상태를 확인했습니다.

## 2026-11-19 복원 보완

- System Events 미실행(-600)을 권한 거부로 오인하던 검사와, Dock 또는 한 창의 실패로 전체 저장을 중지하던 동작을 수정했습니다.
- 최소 30초 관찰, 지연된 크기 변경 재복원, 실패한 대상만 보호·재시도하도록 변경했습니다.
- AppKit 접근성 애니메이션과 연속 위치·크기 쓰기 충돌을 처리합니다. 같은 종류의 처리 참고: [Rectangle의 Enhanced UI 처리](https://github.com/rxhanson/Rectangle/blob/main/Rectangle/AccessibilityElement.swift).
- 검증: 핵심 시나리오 12개 통과. 실행 중인 cmux를 축소하고 8초 뒤 다시 축소한 뒤, 원래 2,112×1,316pt로 두 차례 복원되고 기존 기준이 보존됨을 확인했습니다. 전체 시스템 잠자기와 다음 날 깨우기는 이 검증에 포함하지 않았습니다.
- cmux의 접근성 모드 변경은 실제로 적용돼도 `AXError.notImplemented`를 반환했습니다. 반환 코드와 관계없이 기존 모드를 복구하고, 검증 뒤에도 원래 활성 상태가 유지되는지 확인했습니다.

## 0.2.3 커서 경계 처리 보완

- 비선택 화면 아래에서 이동 이벤트를 버리거나 커서를 강제로 워프하던 처리를 제거했습니다. 아래쪽 압력만 보정하고 모든 이동 이벤트를 전달합니다. 위로 빠져나가는 이동, 좌우 이동, Option 우회와 아래 화면으로의 이동을 유지합니다.
- `./scripts/test-pointer.sh`로 방향별 처리와 우회를 검증합니다. `./scripts/test-pointer.sh --live`는 실제 커서를 잠깐 옮겨 검증합니다. 기존 Dockpin을 먼저 종료하고 약 5초간 입력을 멈춰야 하며, 실제 입력이 들어오면 중단합니다.
- 실제 두 번째 DELL 화면 아래에서 2초간 누르기, 옆으로 이동, 위로 빠져나오기를 확인했습니다. 39개 이동 이벤트가 모두 전달됐고 Dock은 원래 화면에 유지됐습니다.
